Como funciona

  1. O caixa toca em PIX e o PDV pede uma cobrança real ao provedor.
  2. O QR Code aparece na janela flutuante. A credencial bancária permanece criptografada no servidor.
  3. Depois do pagamento, o Firebase consulta a API oficial e confere o ID e o valor.
  4. Somente com estado approved o estoque baixa, a entrada é registrada e a venda termina sozinha.

Conector pronto: Mercado Pago. O modo manual continua disponível para qualquer chave PIX.

1. Configuração do Firebase — feita uma vez

Plano: Cloud Functions exige o plano Blaze com faturamento vinculado. Existem franquias gratuitas, mas Firebase e provedor podem gerar custos conforme o uso.

  1. Instale Node.js LTS e Firebase CLI.
  2. Abra o PowerShell dentro da pasta do PDV e execute:
npm install -g firebase-tools
firebase login
firebase use pdv-brown
npm --prefix functions install

Crie uma chave aleatória de 32 bytes:

$pixBytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($pixBytes)
[Convert]::ToBase64String($pixBytes)

Copie o resultado e cadastre o segredo:

firebase functions:secrets:set PIX_CREDENTIALS_KEY

Por fim, publique:

firebase deploy --only functions,firestore:rules,hosting

Nunca coloque PIX_CREDENTIALS_KEY, Access Token ou JSON de conta de serviço no HTML ou em um repositório público.

2. Conectar o Mercado Pago — cada lojista

  1. Tenha uma conta Mercado Pago apta a receber PIX e uma chave PIX cadastrada.
  2. Entre em Suas integrações e crie uma aplicação de Checkout Transparente.
  3. Abra Credenciais de produção e copie o Access Token, normalmente iniciado por APP_USR-.
  4. No PDV, entre em ADM → Aprovação automática do PIX.
  5. Escolha Mercado Pago — automático, cole o token e clique em Salvar e validar conexão.

O campo fica vazio depois de salvar porque o token foi enviado ao backend e criptografado. O PDV nunca deve pedir senha da conta, código SMS ou senha do e-mail.

Webhook usado pelo sistema

https://southamerica-east1-pdv-brown.cloudfunctions.net/mercadoPagoWebhook

A cobrança já envia essa URL. Se o painel permitir configurar notificações, use-a no ambiente de produção para eventos de pagamento.

3. RecargaPay e outros bancos

RecargaPay

Use o modo manual com a chave PIX. Para automatizar, peça ao atendimento/comercial uma API empresarial Pix Cob, credenciais de servidor, webhook, método de assinatura, homologação e tabela de tarifas. Sem API oficial liberada para a conta, um comprovante ou QR estático não confirma o pagamento com segurança.

Efí, Asaas, PagBank e bancos tradicionais

Cada instituição usa autenticação e campos diferentes. Solicite documentação oficial, endpoints de homologação/produção, client_id, client_secret, webhook e certificado mTLS quando exigido. Um novo conector precisa ser programado nas Cloud Functions antes de aparecer nesta tela.

Não cole certificado, senha bancária ou segredo de outro banco no campo Mercado Pago. Arquivos .p12/.pem pertencem ao backend/Secret Manager, nunca ao navegador.

4. Teste final

  1. Abra o caixa e faça uma venda pequena, por exemplo R$ 1,00.
  2. Selecione PIX e pague usando uma conta diferente da conta recebedora.
  3. Não clique em finalizar. Aguarde a confirmação automática.
  4. Confira venda, estoque, entrada no caixa e extrato do Mercado Pago.

Credencial de produção movimenta dinheiro real. Se ficar aguardando, verifique a internet, use Testar conexão salva e consulte os logs das Functions no Firebase.

Regra importante: não altere o carrinho depois de gerar o QR. Se o valor divergir, o sistema bloqueia a finalização automática e exige conciliação manual.
